# S/4HANA SQL Desk

S/4HANAのDB障害調査に使う、社内配布向けの日本語SQLリファレンスです。検索、症状別カテゴリ、SQLのコピー・保存、結果の見方、権限・負荷の注意、SAP公式資料へのリンクを備えています。

## すぐに開く（インストール不要）

`dist/index.html` をChrome、Edge、Safariなどのブラウザーで開きます。同じ `dist` フォルダーのファイルをすべて保持してください。JavaScriptを有効にしてください。

アプリの表示・検索にはネット接続、Node.js、npm、Python、SAP接続、ログインは不要です。外部フォント、CDN、解析タグ、外部APIは使用しません。公式資料のリンクを開くときのみインターネット接続が必要です。

ブラウザーの規則でコピーが許可されない場合は、選択されたコードをCtrl+C（Macでは⌘C）でコピーするか、`.sql` ボタンから保存してください。

## ローカルURLで開く

Python 3を利用できる場合、フォルダー内で以下を実行します。追加パッケージは不要です。

```sh
python3 start.py
```

Windowsは `py -3 start.py` でも起動できます。Mac用 `start.command`、Windows用 `start.cmd` も同梱しています。

ブラウザーで **http://127.0.0.1:8765** を開きます。サーバーはこのPCのループバックだけを使用し、社内LANへ公開しません。終了は起動したターミナルでCtrl+Cです。ポートが使用中なら `python3 start.py --port 8766` を使います。再起動後は同じ手順で起動してください。

## 対象と実行方法

- **対象:** HANA 2.0を利用するS/4HANAオンプレミス／Private Cloudで、DBの参照権限を持つ運用・Basis担当者。参照した基準はSAP HANA Platform 2.0 SPS 08です。SQLごとの資料リンクを確認してください。
- **対象外:** S/4HANA Cloud Public Edition、HANA Cloud向けSQL保証、ABAP Open SQL、業務テーブルの直接更新。
- 原則として対象S/4HANAの**テナントDB**へ接続します。SQL詳細にSYSTEMDB指定があれば接続先を切り替えます。Private CloudのDBアクセス可否は契約・社内運用に従います。
- アプリはDBへ接続・実行しません。SQLを1つずつ社内で許可されたHANA SQLコンソールへコピーします。接続情報・認証情報はアプリに保持しません。
- SELECTのみでも処理負荷があります。「想定負荷」は比較用の目安であり保証ではありません。TOP/LIMITは返却行数を制限しても、走査・並べ替え全体を制限しません。
- 監視ビューは参照権限により表示が絞られる場合があります。0件でも、権限不足、収集無効、履歴消失などの可能性があります。DB全体の表示が必要な場合はDB管理者に依頼してください。CATALOG READ等の権限を本アプリから付与する機能はありません。
- SQL本文、ユーザー、ホスト、テーブルなどの結果には社内情報が含まれます。結果の保管・共有は社内規程に従ってください。
- SQLはSAP公式資料のビュー・列定義と照合したものです。**社内のHANA実機での実行検証はしていません。** 利用するリビジョン、権限、収集設定との適合を確認してください。

## 症状からの使い方

1. 初回は「接続・事前確認」で接続先・バージョンとビュー列を確認します。
2. 応答が遅い場合は「性能・遅いSQL」。過去の高負荷SQLと現在実行中の状態を区別します。
3. 更新が待たされる場合は「ロック・接続」。HANAのDBロックとABAPのエンキューロックを区別します。
4. メモリ不足は「メモリ・テーブル」、容量不足は「ディスク・ログ」、サービスやバックアップの問題は「稼働・バックアップ」を確認します。
5. 採取時刻・DB・リビジョン・利用SQL IDを記録し、平常時やABAP側のログと照合します。

ABAP側の調査例：ST22（ダンプ）、SM21（システムログ）、SM50/SM66（ワークプロセス）、SM37（ジョブ）、SM12（エンキューロック）。使用できる画面・権限は環境に従います。参照：[SAP HANA Troubleshooting and Performance Analysis Guide](https://help.sap.com/docs/SAP_HANA_PLATFORM/bed8c14f9f024763b0777aa72b5436f6/04861b1e6bc64909be67909e429dcd27.html)、[SAP公式 System Privileges](https://help.sap.com/docs/SAP_HANA_PLATFORM/52715f71adba4aaeb480d946c742d1f6/2a942546f16846d597177b3bfbd1df04.html)。

## 配布・保存

`s4hana-sql-desk.zip` を社内の配布場所へ置き、各PCへ展開して使えます。ブラウザーだけで使う場合は `dist` フォルダー全体の配布でも構いません。自動アップデートはありません。

SQL単体は各詳細画面の `.sql`、全件は左メニューの「SQL集を保存」または同梱の `dist/all-queries.sql` から取得できます。全件ファイルはリファレンス用であり、一括実行用ではありません。スマートフォンなど小さい画面では、一覧のSQLを選択すると詳細へ移動します。

## ファイル構成と更新

| ファイル | 用途 |
| --- | --- |
| `dist/index.html` | 入口・利用ガイド |
| `dist/styles.css` | ローカルのスタイル |
| `dist/app.js` | 検索・表示・コピー・保存 |
| `dist/catalog.js` | 検証済みデータを組み立てたSQLカタログ |
| `dist/all-queries.sql` | 注意点と出典を含むSQL全件 |
| `research/*.json` | 編集用のSQL原本・資料リンク |
| `build.py` | JSONを検査し配布ファイルを更新 |
| `start.py` | Python標準機能のローカルサーバー |

SQL原本を更新した場合は `python3 build.py` を実行します。構造、IDの重複、SQLが単一のSELECTであること、必要情報とSAP公式リンクの有無を検査します。この検査はHANA SQLパーサーや実機実行検証を代替しません。
