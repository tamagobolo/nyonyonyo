# Detour による代替案の探索

本スキルは [Cocoda の事例](https://cocoda.design/varhirac/p/pe1f4d8e389b2) を参考に独自再構成したもの。カナリーの原本・公式配布物ではない。

目的、通常案、現状の根拠、固定制約、動かせる前提を確認する。既存契約・権限・データ整合性やユーザーの明示条件を、発散のために暗黙に捨てない。

1. 通常案を簡潔に記録する。
2. 画面構造、タイミング、作業順、担当など、動かせる前提を1つ選ぶ。何を動かすかを明示する。
3. 構造の異なる代替案を少数出す。必要なら新規実装を増やさない設定・運用上の解決も比較する。制約を仮に外した案は思考実験と表示する。
4. すべての案を固定制約へ戻し、再利用できる部分、追加費用、互換性、運用負担、未確認事項を評価する。制約を満たせない案は不採用または別途の変更提案にする。
5. 通常案との比較から推奨案と不採用理由を示す。最も新しい案や最も複雑な案を優先しない。

出力：動かした前提 / 通常案と代替案 / 目的への効果 / 固定制約との適合 / 根拠 / コスト・不確実性 / 採否。最終的に何を要件や設計へ反映するかが分かるようにする。

候補生成だけで仕様を変更しない。決定権が既に委任されていればその範囲で判断し、境界を超える変更だけを選択肢として提示する。実装や外部操作は依頼された範囲に限る。
