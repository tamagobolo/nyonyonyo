# Persona による設計比較

本スキルは [Cocoda の事例](https://cocoda.design/varhirac/p/pe1f4d8e389b2) を参考に独自再構成したもの。カナリーの原本・公式配布物ではない。

目的、現状の根拠、確定要件、固定制約、動かせる前提を入力にする。未指定の利用者像は仮説と明記する。コードで確認できる事実は調査し、業務上の決定だけを質問にする。

1. 操作・情報・責任が異なる視点を選ぶ。通常は主利用者、制約のある利用者、運用者など2〜4視点で十分。属性を勝手に決めつけず、課題に関連する能力・権限・状況を使う。
2. 全視点へ同じ確定要件と固定制約を適用する。各視点で、目的、必要情報、成功条件、失敗しやすい状態、復帰方法を整理する。
3. 現行案との差を比較する。表示の好みだけでなく、情報構造、操作順、判断に必要な説明を評価する。
4. 視点間の衝突を明示し、両立方法または意思決定者への選択肢を示す。
5. 採用候補を検証可能な受入条件の案として出す。確定していない案を既存要件に混ぜない。

出力：視点 / 成功条件 / 根拠・仮説 / 不足・衝突 / 改善候補 / 検証方法。参照したファイルを示し、採用判断が必要な箇所を明示する。保存先が指定されていればその文書へ、なければ会話で提示する。

単一セッションで視点を切り替えて実行できる。実装、外部送信、PR作成などはユーザーから依頼された範囲に限る。原因が明らかな局所バグ修正へ、不要な人格比較を追加しない。
