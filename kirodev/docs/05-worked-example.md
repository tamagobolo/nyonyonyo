# 記入例：既存 SaaS の CSV 出力を改善する

[入口](../README.md) · [変更依頼テンプレート](../templates/change-brief.md)

**以下は架空の練習例です。** 対象リポジトリの実装を調査した結果ではありません。上限件数、役割、モジュール名、採否はこの例だけの設定で、実プロジェクトでは根拠を確認して置き換えます。テスト結果は未実行です。

## 依頼を具体化する

想定する現状：一覧画面には絞り込みと CSV 出力があるが、出力対象の条件が分かりにくい。出力は既存の同期 API を使い、閲覧者と管理者という権限区分がある。

改善の目的：管理者が「今の絞り込み条件で何を出力するか」を把握して実行でき、失敗時に条件を保持したまま再試行できること。

固定する制約：既存の列順・文字コード・API 契約・権限制御を維持する。新規のバックグラウンドジョブ、メール通知、保存履歴は今回の対象外。上限は練習用に **1,000件**とする。

## 3つのスキルを適用する

| 視点・モード | 得られた候補 | 評価と採否 |
|---|---|---|
| Persona：管理者 | 現在の条件と対象範囲を出力前に表示 | 目的に直結するため採用。件数取得の実装可否は調査事項 |
| Persona：閲覧者 | ボタン表示とサーバーの認可を一致させる | UI と API の両方で確認。既存の権限ルールを変えない |
| Persona：運用担当 | 失敗時に問い合わせへつなげる情報を出す | 既存の問い合わせ経路を表示。存在しない追跡IDは生成しない |
| Detour：別のタイミングで届ける | 非同期ジョブで作成しメールで通知 | 今回は運用と契約の変更が大きいため不採用 |
| Detour：新しい画面を作らない | 一覧画面の出力操作の近くに対象条件を表示 | 小さい変更で迷いを減らせるため採用 |
| Thriller：失敗から戻る瞬間 | エラー時にもフィルタを保持し、再試行できる | 最重要体験の改善として採用。二重操作時の挙動も確認 |

これは同梱スキルの手順を用いた著者側の適用例であり、Kiro 実機で生成・検証したログではありません。

## 受入条件に落とす

| 要件ID | 条件 | 期待する振る舞い |
|---|---|---|
| R-1 | 管理者が条件 F で一覧を絞り込み、CSVを要求 | 出力対象は同じ条件 F に一致し、既存の列順と文字コードを維持 |
| R-2 | 出力権限がない利用者が直接APIを呼ぶ | 既存の認可契約に従い拒否し、CSVデータを返さない |
| R-3 | 対象が1,000件を超える | 出力を開始せず、条件を絞り込む案内を表示 |
| R-4 | 対象が0件 | 空であることを表示し、不要な出力処理を開始しない |
| R-5 | 出力要求が失敗する | 絞り込み条件を保持し、失敗したことと再試行方法を示す |
| R-6 | ブラウザへCSVの応答を正常に渡す | 出力処理の進行表示を解除する。利用者がファイルを保存済みとは断定しない |

未決定の質問：件数と出力データの間に更新が起きた場合の整合性をどう扱うか。初回検討では、サーバー側で上限を最終判定し、フロントの事前表示を保証値と扱わない案を技術責任者へ提示する。

## 設計を決める

採用方針：既存のフィルタ表現と出力 API を利用する。認可・上限の判定はサーバーで維持し、画面側は利用者の判断と復帰を補助する。新規キューと通知経路は作らない。

調査で確認する箇所：一覧のフィルタ状態、APIのフィルタ変換、認可関数、CSV生成関数、ダウンロード失敗時の状態処理、既存テスト。実在パスはここでは作りません。

状態の例：待機 → 実行中 → 応答受領 / 失敗。二重クリック時は同じ操作を多重に開始しない。失敗から待機へ戻る際もフィルタは保持する。

## タスクと証拠を対応させる

| タスク | 依存 | 対応要件 | 完了を示す検証 |
|---|---|---|---|
| T-0 現行仕様と契約の調査 | なし | 全体 | 実ファイル根拠、既存テストの基準結果 |
| T-1 サーバーの認可・条件・上限の確認と不足修正 | T-0 | R-1/R-2/R-3 | 権限、境界件数、条件付き出力の結合テスト |
| T-2 画面の対象条件・状態・再試行の改善 | T-0、T-1で契約確定 | R-3/R-4/R-5/R-6 | 0件、超過、失敗、再試行、多重操作のテスト |
| T-3 統合して受入条件を検証 | T-1/T-2 | 全体 | UI操作とAPI結果の整合、既存CSVとの比較 |
| T-4 文書更新・公開引継ぎ | T-3 | 全体 | 受入結果、変更差分、回復手順、観測項目 |

## マネージャーとシニアの指示例

マネージャーの依頼：「CSV出力の対象条件と、失敗時の再試行を分かりやすくしたい。既存 API と CSV 形式を維持し、今回は R-1〜R-6 を対象にする。非同期通知は対象外。技術責任者に件数整合性とテスト方針の判断を依頼する。」

シニアの実装指示：「確定した契約をもとに T-2 を実装する。既存のフィルタ状態を再利用し、0件・上限超過・失敗・応答受領を分ける。成功表示はブラウザへの応答受領を意味し、ファイル保存完了とは表示しない。認可処理の置換は今回の範囲外。既存の検証コマンドを確認して結果を添付する。」
