# 案件固有の判断基準 — 記入例

必要な欄だけ、対象リポジトリの既存文書に取り込む。新しい文書を置く場合は対象の `AGENTS.md` または `*-local` スキルから参照する。本文の未記入欄を事実として扱わない。

## 正解とみなす状態

- 対象と主要な利用者: （記入）
- 現行仕様 / 設計の原本: （実在するパス）
- 用語と意味: （同じ概念を指す正式名称。名称を変更する範囲は必要な箇所だけ）
- 維持する契約・制約と理由: （例外の条件も記入）
- 関連するRDR / ADR: （存在する場合のパス）

## 合格とみなす条件

|変更の種類|最小の検証コマンド / 確認方法|入力・期待結果|追加検証が必要になる条件|
|---|---|---|---|
|文書・設定|（その形式と参照先の確認）|（記入）|（記入）|
|振る舞い|（既存の対象テスト）|（記入）|（共有API等への影響）|

必須CIチェックがある場合はここに記載する。実際に動かせるコマンドだけを採用し、未実行は未実行と記録する。

## 危険とみなす条件

- この案件で個人情報・機密とするデータ、合成データの使い方: （実値を書かず分類を記入）
- 書き込み・外部送信・公開が認められる対象: （現在の権限を参照）
- 公開前の検査 / CI検出 / 混入後の対応: （既存hook・CI・手順のパス、未導入なら未導入）

## 固有の手順が必要な場合

例えば `.agents/skills/codebase-watch-local/SKILL.md` に次の最小定義を置き、上記の実在する文書へつなぐ。全スキルの複製は不要。

```markdown
---
name: codebase-watch-local
description: このリポジトリをcodebase-watchで点検する際の固有ルールを補足する。
---

共通のcodebase-watchを使い、このプロジェクトのAGENTS.mdが指す個人情報の定義、公開条件、検証コマンドを確認する。
根拠がない項目は未確認とし、追加定義だけで操作の権限を広げない。
```

`codebase-atlas-local` / `agent-fit-review-local` も同じ命名規約で必要な場合だけ作れる。共通手順を先に読み、固有部分を追加で読む運用である。
