# 設計改善のHTMLレポート

対象、作成時点、現状と提案の区別を先に示し、重要な少数の候補を比較する。各候補にファイル位置、現状図、提案図、具体的な問題、変更後の契約、利点と移行上の懸念を置く。必要な説明を固定文字数へ無理に切らない。

図の種類は判断する内容に合わせる。依存・責務は構造図、呼出の順序はシーケンス、状態は状態遷移を使う。代表的な流れのHTMLには同梱の `$archify`、全体のファイル関係を探索する場合は `$codebase-atlas` を使う。短い比較ならインラインSVGとCSSでもよい。

配布HTMLはローカルで単独閲覧できるようにし、CDNのTailwindやMermaidへ依存させない。テキスト・ソース情報はエスケープし、関係に意味と方向を付ける。提案した結線を現行コードの事実として描かない。

意味の異なる項目だけ色を分け、文章と線種でも判別できるようにする。日本語の長いラベル、代表的な画面幅、検索や詳細を追加した場合の操作を実表示で確認する。既存UIを変更していない場合に全体のUIテストやビルドを繰り返さない。
