# Code Review

依頼されたPR・コミット・差分を対象とする。指定がない作業中レビューでは現在の変更と周辺コードから範囲を定め、対象を明記する。ベース、未追跡ファイル、作業途中の範囲が結論に影響するときだけ不足情報を確認する。

対象のAGENTS.md、既存仕様・テスト、呼出側、変更理由を読む。仕様が取得できなければその限界を明記し、コードから確かめられる欠陥のレビューを進める。課題管理サービスへの接続や新規チケットを前提にしない。

二つの観点を確認する。同じ人が連続して確認してよい。独立性や文脈の分離が役立つ大きい差分でのみ、範囲を分けて委譲する。

- **仕様**: 期待する振る舞い、失敗時の扱い、互換性、データと権限の制約を満たすか。仕様のない推測を要件として扱わない。
- **実装**: 到達する不具合、抜けた分岐、誤った状態・リソース管理、影響に合わない検証、具体的な重複や過剰な仕組み。既存設計を尊重し、好みだけの指摘は欠陥に数えない。

指摘を出す前に実際の呼出経路と反証を確認する。必要なら最小の再現・関連テストを使う。各指摘は重大度、ファイル:行、発生条件、影響、修正方向を簡潔に示す。仕様上の不明点と確認済みの欠陥を区別する。

最終回答は重要な指摘を先に示し、対象範囲、実行した検証、未検証の限界を添える。指摘がなければその旨を述べ、完全性は主張しない。レビューだけの依頼でファイル修正や外部への投稿を行わない。過剰設計の精査には必要に応じて `$ponytail-review` を使う。
