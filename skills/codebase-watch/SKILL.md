# Codebase Watch

最初に [共通作業方針](../codebase-atlas/references/common-workflow.md) を読む。最小の変更・検証、案件固有の `codebase-watch-local`、判断の記録、読み取り担当としての進め方を適用する。

対象と前回の出力先を確認し、新しい観測が必要な場合はこのスキルの `scripts/run.py` をPython 3.11以上で実行する。

```bash
python3 <このスキルの場所>/scripts/run.py scan --root <対象> --out <対象>/.observatory
```

同じ出力先の `report.json` が基準値になる。初回は差分なし。既存の基準値を消して差分を隠さない。異なる対象・除外条件・上限と比較しない。`coverage.complete=false` の場合は読取不完全として報告し、未観測を削除や解消として扱わない。

チェック範囲・トリアージと個人情報保護は [references/review.md](references/review.md) を読む。独立した評価が役立ち、利用できる場合は `codebase_sentinel` にレポートと該当ファイルを渡し、到達性・権限・実行条件を確認させる。それ以外は親が確認する。結果を親が照合する。モデル設定を勝手に固定しない。

継続監視の実行を依頼された場合、対象と周期を決める。Codexの定期実行ツールが使える場合は現在のスレッドのheartbeatを優先し、既存の同目的の定期実行を更新する。ローカルで開発中の変更検知には以下も使える。スキル作成や一回の点検だけの依頼で、常駐処理や定期実行を勝手に開始しない。

```bash
python3 <このスキルの場所>/scripts/run.py watch --root <対象> --interval 30
```

watchはCtrl-Cで停止する。同じ出力先の多重起動は拒否し、変更があったときだけHTML/JSON/Markdownと履歴を更新する。HTMLは保存時点のスナップショットなので、再読込または新しいJSONの読込で更新する。

CIでは `scan ... --fail-on high` を使用できる。終了0は今回の指定条件を通過、1は設定した重要度以上の兆候、2は読取/解析/入力の不備。1を確定した脆弱性件数と呼ばない。現在のコードを実行する追加テストや外部スキャナは、利用可能性・実行範囲・送信データを確認して実施する。

担当の追加/統合/削除は `$agent-fit-review` に渡す。変更・削除の依頼がある場合も、対象ファイルと根拠を具体化し、既に得た権限の範囲で進める。

返すもの: 新しい問題、解消候補、設定やhooksの変更、重要度・確度・ファイル行・次の検証、監視の稼働状態。単なるファイル更新時刻からエージェントの稼働を断定しない。
