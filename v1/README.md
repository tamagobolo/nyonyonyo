# ワークスペース開発ガイド v1

このガイドは、複数のプロジェクトを同じローカルワークスペースで扱い、Codex と共同で開発するチームのための資料です。作業対象を特定し、根拠を集め、変更・検証・共有まで進める方法をまとめています。共有先は `tamagobolo/nyonyonyo`、本版の格納場所は `v1/` です。

初版資料は既存の場所に保存したまま、本版を追加しています。`v1` は資料のフォルダ名です。Git タグや GitHub Release の作成を意味しません。

[検索・コピーができる HTML ガイド](guide.html) は、このフォルダ一式を取得してブラウザで開きます。本文はオフラインで読めます。GitHub の通常のファイル画面では HTML は実行されません。上位フォルダの実コードへの参照もたどる場合は、リポジトリ全体を取得してください。

## このワークスペースで守る3つの前提

1. **ワークスペースと Git リポジトリを分ける。** ローカルの親フォルダは複数プロジェクトを置く場所で、親全体が一つの Git リポジトリではありません。変更先・実行するディレクトリ・アップロード先を依頼ごとに合わせます。
2. **配置されていることと、利用可能であることを分ける。** スキルの原本、読み込まれたスキル、エージェントの設定、実行権限は別々に確認します。
3. **実ファイルの事実と提案を分ける。** このガイドの運用はチームへの提案です。実際の `AGENTS.md`、依頼、仕様、既存の検証・公開手順を読み、対象に合わせて使います。

| 場所 | 内容 |

図は [マネージャー](diagrams/manager-workflow.html) と [開発者](diagrams/developer-workflow.html) の2種類です。図の文章は日本語、拡大・検索・テーマ切替など固定の Viewer UI と HTML の言語属性は英語です。本文の手順と合わせて読みます。

3つのスキルは、紹介記事の着想をこのワークスペース向けに独自に再構成したものです。記事執筆者の公式実装や、確認済みの上流 GitHub スキルとしては扱いません。[出典と確認範囲](sources.md) に経緯を記載しています。

## 今日から始める

対象のプロジェクトで、[プロジェクト把握テンプレート](templates/project-context.md) の「対象・基準」を埋めます。次に [変更依頼テンプレート](templates/change-brief.md) の目的と受入条件を記入します。小さな変更なら、この2つを依頼本文の中に短くまとめるだけでも構いません。

本版のスキルを使う場合は [導入手順](docs/07-adoption-and-maintenance.md) を先に確認してください。`v1/` に置かれたスキルが、ワークスペース全体に自動で有効になるわけではありません。
