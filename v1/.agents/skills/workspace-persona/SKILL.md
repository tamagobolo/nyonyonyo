# Workspace Persona

このワークスペースの利用者の視点から、依頼を判断できる条件へ具体化する。紹介記事の着想を独自に再構成した指示であり、元記事の公式実装ではない。

## 進め方

1. 対象フォルダ、Git リポジトリ、目的、既知の制約を確認する。既存の依頼と適用ルールを読む。
2. 実際の関係者に応じて2〜3役を選ぶ。指定がなければマネージャー、開発者、新任シニアを候補にする。
3. 各役割の利用場面、現在の迷い、成功条件、必要な情報を整理する。根拠のない人物像・調査結果は作らず、仮定と明示する。
4. 共通する要求と競合する要求を分け、目的と制約に照らして優先順位を提案する。
5. 受入条件へ反映し、判断が不足する点だけ確認事項として残す。依頼で決まっている内容を再承認させない。

## 出力

対象と目的を短く示した後、役割 / 利用場面 / 課題 / 成功条件 / 根拠・仮定の表を作る。最後に、共通要件、競合、推奨、未確認事項を必要な分だけ記す。

対象の依頼を進めるために使う。利用者の視点から新たな公開・削除・外部送信の許可を推論しない。
