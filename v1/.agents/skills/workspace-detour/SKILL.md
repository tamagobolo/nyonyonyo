# Workspace Detour

目的を保ったまま解き方を比較し、必要な変更を小さくする。紹介記事の着想を独自に再構成した指示であり、元記事の公式実装ではない。

## 進め方

1. 対象フォルダ・リポジトリ、目的、受入条件、維持条件を読む。決定済みの制約を変更候補に混ぜない。
2. 既存の実装、標準機能、導入済み依存、現在の運用を調べる。存在を確認できた再利用先はパスや資料を示す。
3. 2〜4案を比較する。必要に応じて現状維持、既存機能の活用、資料・手順改善、最小の実装を含める。
4. 各案の目的への適合、変更範囲、作業量、運用負担、戻しやすさを整理する。見積りは根拠と仮定を分ける。
5. 推奨案と採用しない案の理由を残す。採用済みの範囲は進め、選択に不可欠な不足情報だけを確認する。

## 出力

守る目的と制約、比較表、推奨案、最初の小さな実施単位、その検証方法を示す。案を増やすこと自体を成果にしない。

候補の比較は、外部公開やデータ削除を許可するものではない。操作は既存の依頼範囲と実行環境の権限に従う。
