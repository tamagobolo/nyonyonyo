# 導入と保守

## ガイドとして使う

このフォルダ一式を GitHub から取得します。`README.md` を入口にするか、`guide.html` をブラウザで開きます。ガイド本体とフロー図の表示にネットワーク接続は不要です。出典の外部ページを開く場合は接続が必要です。

図の HTML では、英語の Viewer UI から検索・フォーカス・テーマ切替などを操作できます。ガイド本体の検索は章単位で、検索語を含む章だけを表示します。コピー機能が使えない環境ではコード範囲が選択されるため、通常のコピー操作を使ってください。

## 3つのスキルを対象の作業で使う

本版の配置は次のとおりです。

```text
v1/.agents/skills/
├── workspace-persona/SKILL.md
├── workspace-detour/SKILL.md
└── workspace-thriller/SKILL.md
```

Codex は、作業ディレクトリから Git リポジトリのルートまでの各階層にある `.agents/skills` を調べます。本版を `v1/` の作業として開くと、この場所が探索対象になります。親の `nyonyonyo/` やワークスペースを開いただけで、下位の本版スキルが全域に有効になるわけではありません。[公式：スキル](https://learn.chatgpt.com/ja-JP/docs/build-skills)

利用する方法は、作業する場所に応じて選びます。

| 場面 | 方法 |
| --- | --- |
| 本版の改善を行う | `v1/` を作業対象にして、3つのスキルが選択できるか確認する |
| 別のプロジェクトで継続利用する | 同名定義がないことを確認し、必要な3つのフォルダをそのプロジェクトの `.agents/skills/` に配置する |
| 一回だけ内容を適用する | 該当する `SKILL.md` のパスを指定し、その内容を読んで作業するよう依頼する |

今回はスキルの原本を本版に同梱しています。ユーザー全体のスキル設定、既存の `.agents/skills`、外部サービスの接続は変更していません。

配置後は `$workspace-persona`、`$workspace-detour`、`$workspace-thriller` の名前と実際のパスを確認します。認識されない場合は配置場所とメタデータを点検し、必要ならセッションを開き直します。既存の同名定義を確認せず上書きしないでください。

## 文書とコードの情報を保つ

対象の仕様・決定は対象リポジトリに置きます。既存の保存先がある場合はそれを使います。ない場合でも、小さな依頼は本文や作業記録で十分です。複数工程にまたがる変更でだけ `docs/changes/〈変更名〉/` などの保管場所を検討します。この名前に自動処理の意味はありません。

| 変化 | 更新する情報 |
| --- | --- |
| リポジトリ・フォルダ・公開先が変わる | 地図、プロジェクト把握、指示文の対象欄 |
| コマンド・実行環境が変わる | 実行場所付きコマンド、出典の基準コミット |
| 入出力の契約・主要な依存が変わる | コードの読み順、設計・引継ぎの説明 |
| スキルの名前・配置・用途が変わる | SKILL.md、導入説明、呼出例、HTML の章一覧 |
| フローが変わる | Markdown と入力 JSON、図の HTML、検証記録 |

役割名は担当者を固定するものではありません。小さな案件で一人が複数の役割を兼ねても、どの判断と検証をしたかが分かれば運用できます。

## HTML ガイドを再生成する

Markdown と SKILL.md が編集原本です。`scripts/build-guide.mjs` がそれらをまとめて `guide.html` を生成します。実行場所は `v1/`、Node.js と `marked` が使える環境が必要です。生成された HTML の閲覧にはこれらの依存は不要です。

既存環境に `marked` があれば次を実行します。

```bash
node scripts/build-guide.mjs
```

別の場所にある `marked` を使う場合は、ESM の入口を引数に渡せます。

```text
node scripts/build-guide.mjs /path/to/marked/lib/marked.esm.js
```

依存が用意されていない場合の一例です。作業用ディレクトリを使い、リポジトリの依存ファイルを変更しません。`marked` はこの版の生成で使った 17.0.5 に固定しています。

```bash
build_tmp=$(mktemp -d)
npm install --prefix "$build_tmp" --no-audit --no-fund marked@17.0.5
node scripts/build-guide.mjs "$build_tmp/node_modules/marked/lib/marked.esm.js"
```

生成前に、Markdown を公開可能な内容としてレビューしてください。HTML を含む任意の未信頼入力を安全に変換するサニタイザーではありません。

## 改訂・共有する

軽微な改善は本版へ追加コミットし、前提が大きく変わる場合は次版を別フォルダに作ります。過去の版は、削除や移行が明示されるまで保持します。

更新時は相対リンク、見出し・呼出例の整合、スキルの形式、画面表示を確認します。図を再生成した場合は、その図の検証と目視確認も行います。最後に変更パスを限定してコミットし、指定された保存先から取得できることを確認します。
