# コピーして使う指示文

`〈対象〉` などの値を実際の依頼に置き換えます。コードブロックの文面は依頼のひな型で、外部操作への一括した許可ではありません。すでに指定された範囲と権限を引き継いで使います。スキルを使う例は [導入と保守](07-adoption-and-maintenance.md) の配置確認後に利用します。

## A. 作業対象を確定する

```text
このワークスペースの〈対象フォルダ〉で作業してください。
最初に、作業ディレクトリ、Git ルート、remote、ブランチ、基準コミット、既存差分、
適用される AGENTS.md を確認し、今回変更する範囲を短く整理してください。
編集元は〈場所〉、共有先は〈リポジトリ・パス〉です。
既存差分を保持し、独立して進められる調査から開始してください。
```

## B. 利用者の成功条件をそろえる

```text
$workspace-persona を使って、〈対象プロジェクト〉の〈課題〉を整理してください。
読み手はマネージャー、開発者、初めて参加するシニアです。
各役割について利用場面、迷う点、成功条件、必要な情報を示してください。
事実と仮定を分け、競合する要望と優先順位を決める材料を出してください。
今回は〈対象外〉を含めません。
```

## C. 解決方法の選択肢を広げる

```text
$workspace-detour を使い、〈目的〉を満たす方法を比較してください。
現状維持、既存コードや設定の利用、手順・資料の改善、小さな実装を候補に含めます。
各案の対象範囲、効果、作業量、運用負担、戻しやすさを比較してください。
推奨案と採用しない理由を残し、採用済みの依頼範囲から実装を進めてください。
```

## D. 最初の成功体験を定義する

```text
$workspace-thriller を使って、〈利用者〉が初めて〈目的〉を達成する場面を設計してください。
例：新任シニアが、対象リポジトリと検証方法を含む最初の指示を出せる。
開始時点、行動、迷い、提示する情報、成功を確認する観測点を示してください。
見栄えや驚きのための追加機能を目的にせず、実務の成果に結び付けてください。
```

## E. コードの入口と変更の影響を調べる

```text
〈リポジトリ・基準コミット〉の〈機能〉を実コードで調べてください。
入口、主要な呼出先、データ形式、出力、対応するテストをつないで説明してください。
根拠は相対ファイルパスと関数名で示し、静的に読んだ関係と実行確認を区別してください。
変更候補は〈範囲〉です。既存の再利用先と、確認が必要な互換性を挙げてください。
```

## F. 小さく実装して確認する

```text
〈対象〉の R1〈受入条件〉を実装してください。
維持する条件は〈既存の振る舞い・互換性〉、対象外は〈範囲〉です。
既存コード、標準機能、導入済み依存を調べてから最小の変更を選んでください。
変更に合う確認を実行し、必要な結果が出たら差分と未確認事項を報告してください。
不要な抽象化、無関係な修正、既存差分の取り消しを加えないでください。
```

## G. 不具合を調べる

```text
〈対象・環境〉で〈入力・操作〉をすると〈実際の結果〉になります。
期待する結果は〈条件〉です。再現条件、観測、仮説を分けて原因を絞ってください。
最小の再現または該当テストで確認し、原因に対応する修正と回帰確認を行ってください。
再現できない場合は、確認した条件と不足情報を示してください。
```

## H. 差分をレビューする

```text
〈基準〉からの〈対象パス〉の変更をレビューしてください。
目的と受入条件は〈要件〉です。仕様の不一致、再現可能な不具合、意図しない変更を確認してください。
指摘には起きる条件、影響、ファイル位置、必要な確認を付けてください。
好みの変更や先回りした仕組みを必須事項にせず、未確認は未確認と報告してください。
```

## I. 旧版を保持して新しい資料を共有する

```text
tamagobolo/nyonyonyo に、ワークスペース専用の開発ガイドを v1/ として追加してください。
既存の資料は元の場所と内容を保持し、新版は実際のフォルダ構成・ルール・操作に合わせてください。
マネージャー用、開発者用、新任シニア向けの導入、指示文、3つのスキルを含めます。
入口の README に新版へのリンクを追加し、リンク・スキル形式・HTML 表示を確認してください。
今回追加する内容だけをコミットして GitHub へアップロードし、URL とコミットを報告してください。
```

## J. 検証と引継ぎをまとめる

```text
今回の変更を、目的、変更範囲、受入条件との対応、検証結果、未確認事項、共有先でまとめてください。
実行したコマンドには作業ディレクトリを付け、定義の確認だけの項目と区別してください。
公開済みの場合はリポジトリ・ブランチ・パス・コミットと取得できるリンクを付けてください。
次の担当者が必要な作業だけを再開できる粒度にしてください。
```
