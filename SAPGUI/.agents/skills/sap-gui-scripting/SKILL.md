# SAP GUI Scripting

目的に必要な操作だけをコードにする。利用者が言語を指定しなければVBScriptを使う。

1. 業務手順、対象のSAP GUI、実行環境、録画または既存コードを確認する。画面IDは録画や実画面から取る。公式APIだけを根拠に個別画面のIDを作らない。不足するIDがあれば、必要な録画箇所を示す。
2. 対象版の[SAP GUI Scripting API](https://pages.community.sap.com/topics/gui/scripting)で、実際に使うメソッドだけを確認する。参照先の例として[8.00 PL01のAPI PDF](https://help.sap.com/doc/9215986e54174174854b0af6bb14305a/800.01/en-US/sap_gui_scripting_api.pdf)がある。利用環境の版が違えばその版の資料を優先する。利用できるか疑わしいときだけ[Security Guide](https://help.sap.com/doc/97d2d0bc2ed248a4a85a0bec608704f8/800.08/en-US/sap_gui_scripting_sec_guide.pdf)を参照する。
3. 録画や既存コードを出発点にし、不要な画面サイズ変更や重複操作を除く。短い処理は順番に書く。汎用フレームワーク、補助関数、設定ファイル、ログ、再試行、待機処理は、その案件で必要な理由がある場合だけ追加する。接続済みのセッションが渡されていれば、それを再利用する。
4. 対象セッションを取り違える可能性がある場合は、システム・クライアント・ユーザーなど必要な条件で識別する。画面遷移後に古い要素を使い続けない。保存や転記の結果が不明なら自動再実行せず停止する。認証情報をコードやリポジトリに入れない。
5. 実施した確認と、未確認のWindows・SAP実機動作を区別して伝える。成果物には、使った公式資料の版・URLと、録画由来の画面IDの出典を簡潔に添える。

コード生成の依頼はファイル作成まで。SAP上の実行は、対象環境と操作範囲が具体的に依頼されている場合に進める。画面IDなどが足りないときは、確定できる部分まで作り、未完成の業務操作を完成品として扱わない。
