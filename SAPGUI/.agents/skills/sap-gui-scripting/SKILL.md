# SAP GUI Scripting

業務手順を、根拠を追えるGUIスクリプトと実行・検証手順に変換する。基本の出力はVBScript `.vbs`。利用者が言語や既存コードを指定した場合はそれに合わせる。

## 入力を確定する

会話・既存コードから、GUI種別と版、言語、対象システム・クライアント・セッションの選び方、業務目的、入力、出力、更新の有無を把握する。質問はコードの正確さに必要な不足情報に絞る。版が不明な段階でも調査や草案は進め、採用した版を明示する。

画面IDは録画、利用者の提供コード、または許可された実画面の確認を根拠とする。IDが不足していれば具体的に必要な録画区間・項目を示す。接続処理など独立した部分を先に作り、未確定の業務処理は明示的に実行を止める。架空IDを入れて完成品としない。通常のスクリーンショットだけでは正確なScripting IDを確定できないことに注意する。

生成の依頼だけでSAPへの実行許可があるとは扱わない。具体的な環境・処理への実行がすでに依頼されていれば、範囲内で進める。

## 公式APIを調べる

[公式資料の索引](references/official-sources.md)から、対象GUIと版に合う資料を開く。使うオブジェクト、メソッド、プロパティ、引数、戻り値、制約を確認する。外部ライブラリを使う場合は、そのライブラリ自身の公式仕様も確認する。

- SAP公式のAPI資料は技術仕様の根拠、録画は個別画面と操作順の根拠として分ける。
- 対象リリースと違う資料しか読めなければ差を明示し、その版で動くと断定しない。
- Web取得ができなければ、利用者が提供した公式PDFやSAP GUI付属ヘルプを使う。それもなければ、参照予定と確認済みを分けて草案を作る。
- コミュニティの個人投稿や記憶だけでAPIの存在を確定しない。資料の長文転載は不要。

## 生成する

[実装ガイド](references/generation-guide.md)を読み、対象に必要な項目を適用する。VBScriptの接続部分には、必要に応じて [inspect-session.vbs](assets/inspect-session.vbs)を参考にする。これは既存セッションの診断用サンプルであり、業務自動化の完成品ではない。

生成コードでは、対象セッションの識別、有限の待機、画面遷移後の再取得、予期しないダイアログとエラーの停止を扱う。保存・転記・削除・送信などの操作は業務要件に対応付ける。更新完了を確認できなかった場合は、同じ操作を自動再試行しない。

入力値と保存先は設定または引数に分離する。ID、メニュー位置、VKey、ALV列名の不明点を推測で埋めない。画面遷移だけでも保存・更新が起こる業務があるので、「保存ボタンの前だから安全」と決めつけない。

## 検証して引き渡す

実施可能な構文・静的検証を行い、Windows/SAPの有無と実行許可に応じて実機確認する。検証環境で対象を絞って確認してから処理範囲を広げる。具体的な処理がない汎用サンプルについて、全業務対応を約束しない。

成果物は依頼された場所へ保存する。このリポジトリでの案件固有の生成物は、指定がなければGit対象外の `output/` を使う。次を添える。

- スクリプト、設定値、前提条件、実行コマンド。
- 主なAPIのオブジェクト名・メンバー名と、公式資料のURL・版・節またはページ。
- 画面IDの出典、未確定箇所、成功条件と停止条件。
- 実際に実施した検証と、未実施のWindows/SAP確認手順。

未確認の画面IDやAPIが残る場合は草案として引き渡す。macOSでのファイル確認やモック試験を、Windowsの構文確認・SAPの実機確認と言い換えない。
