# スクリプト生成の判断基準

以下はこのパッケージの実装方針。SAPの規則そのものとは区別する。APIの仕様は [公式資料](official-sources.md)の該当箇所で確認する。

## 実行環境と言語

VBScriptならWindows Script Hostが利用できることを確認し、`Option Explicit`を使う。日本語を含むファイルは対象Windowsでの文字コードを確認する。ASCIIだけのサンプルを日本語化した際に、そのまま動くと仮定しない。VBAならOffice上で動くモジュールとして作り、`WScript`やVBScript専用構文を持ち込まない。PythonならWindowsとCOM連携ライブラリの導入条件を記載する。ホストの32/64bitやSAP GUI版の組み合わせに問題があれば公式資料・導入環境を確認する。

## セッションと識別

既存のログイン済みセッションに接続する構成を基本にする。`Children(0)`を無条件に対象とせず、システムID、クライアント、ユーザーで一致を確認する。同じ条件のセッションが複数なら、利用者が指定したセッションID・番号や開始画面の条件で絞る。候補が0件または複数件なら停止する。

明示された接続番号・セッション番号を使う構成でも、取得後の識別照合は必要。番号は永続的な識別子ではない。探索に失敗した候補を無言で飛ばして、残った1件を正しい対象と扱わない。サーバーでScriptingが無効な場合、セッションの列挙自体が失敗し得る。

ログイン、接続新設、セッション終了は利用者の要件に含まれる場合だけ実装する。パスワードの埋め込みを避ける。セッション情報だけではABAPのRFCリダイレクト先まで保証できないため、そのような業務では対象システムの追加確認を設計する。

## 操作と待機

処理開始時に識別条件と開始画面を検証する。通信後は `Busy` と期待する画面・要素を確認して進む。待機には期限を設ける。`Busy` のポーリングはCOM呼び出しそのものを強制中断する機能ではないので、すべてのハングが指定時間内に解除されるとは説明しない。

画面遷移・通信でコントロールの参照が無効になり得る。遷移後に `FindById` で再取得する。`FindById(id, False)`を使う場合も、戻り値の存在と期待する型を確認する。IDの不在とCOM接続エラーを混同しない。

未知のダイアログは自動でEnter・Yes・OKを押さず停止する。既知のダイアログだけ、画面ID・タイトル・意味と実行権限を照合して処理する。固定のSleepだけで画面準備を判断しない。

## 入力・表・出力

録画の不要なフォーカス移動や画面サイズ変更は、操作上不要と確認できたものだけ除く。`SendVKey`の数値やメニュー番号を記憶で補完しない。識別子、先頭ゼロ、日付、桁区切り、桁数はSAP側の形式に合わせる。ユーザー入力をスクリプトに直接連結する場合は引用符を適切に処理し、コード注入を避ける。

`GuiGridView`と`GuiTableControl`を区別する。ALVの列キーを表示ラベルから推測しない。表のスクロールでは可視行と絶対行の違いをAPIで確認する。既知の行数・終了条件を設け、再取得やスクロール後に行の重複・欠落を確認する。

エクスポートではフルパス、拡張子、既存ファイルの扱いを明示する。ローカルファイルの上書きやExcelの自動起動は要件と実環境に合わせる。ネイティブのファイルダイアログ等がScripting APIで扱えるとは仮定しない。

## 停止・再実行・確認

VBScriptの `On Error Resume Next` は例外を調べる短い区間に限定し、直後に `Err.Number` を保存して `On Error GoTo 0` に戻す。長い業務処理全体にエラー無視を設定しない。

ステータスバーの `MessageType` を確認し、E/Aはエラーとして停止する。Wは意味を確定した場合だけ続行する。Sだけで業務成功を決めず、想定メッセージ、生成番号、画面、出力ファイル等、その操作に対応する成功条件を確認する。エラーメッセージやログに業務データが含まれる場合は必要な箇所を伏せる。

更新系の依頼では更新箇所を明示し、既定では明示的な実行設定を要求する。確認モードを設けるなら更新操作・更新につながる画面遷移を実行しない設計にし、単なる「最後の保存省略」をdry-runと呼ばない。保存・転記後に応答が途切れたら結果不明として停止する。更新を再送する前に、業務キー等で処理済みか確認する。

実機で確かめる場合は、対象識別、通常経路、対象不一致、要素不在、待機期限、予期しないモーダル、SAPエラー、重複実行の影響を処理に応じて確認する。WindowsやSAPがない環境では静的検証の結果と実機用の手順を渡す。
